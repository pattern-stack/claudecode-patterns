# Add gate-mode mechanism + Status taxonomy (SDLC opinion v2.1)

## Goal

Wire the gate-mode resolution code that consumes the `gate1_default: strict` key shipped in PR 1. Specifier reads `gate:auto`/`gate:human` labels at runtime. `/sync-issues` stamps those labels at issue-creation time by reading plan.yaml's optional `auto_approve` knob. Implementer's hard refusal-without-`state:strategy-approved` is preserved structurally.

Plus: ship the 9-option outcome-driven Status taxonomy as documentation in the github + linear primitives.

## Approach

Resolution timing is **at sync, not at design**:
- `/sync-issues` reads `plan.yaml.auto_approve`. For each leaf issue, stamps `gate:auto` (auto-approve mode) or `gate:human` (forced strict) on creation.
- Specifier reads issue labels only — never reads plan.yaml. Resolution at runtime: `gate:auto` → auto; `gate:human` → strict; no `gate:*` → fall through to `sdlc.yml.gate1_default`.
- Auto mode behavior: specifier posts strategy + sets `state:strategy-approved` directly + does not halt.
- Strict mode behavior: unchanged (post strategy + `state:awaiting-strategy-review` + halt).

Implementer's gate stays a hard refusal on missing `state:strategy-approved`. Auto mode just satisfies it via the agent.

Linear taxonomy: working hypothesis from plan + user input (Backlog→backlog state; On-Deck/Planning/Ready→unstarted; In Progress/In Review→started; Done→completed; Cancelled→canceled; Blocked→unstarted+label). Documented in linear.md primitive; specifier proposes final mapping in subsequent specs as needed.
