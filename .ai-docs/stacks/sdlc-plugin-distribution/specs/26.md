# Add `/sdlc:link-project` — discover and cache GitHub Project field IDs

## Goal

New slash command at `plugin/commands/link-project.md` that discovers GH Project v2 field IDs (project ID, Status field ID, option IDs for the 9-option taxonomy) and caches them to `.claude/project.json`. Pulls discovery out of specifier's hot path.

## Approach

GraphQL one-shot discovery via `gh api graphql`. Supports both user-scoped (`github.com/users/<u>/projects/<n>`) and org-scoped (`github.com/orgs/<o>/projects/<n>`) URLs. Idempotent re-run. Cache file is gitignored by default (per PR 1's gitignore update).

Specifier (in PR 2) reads the cache and degrades gracefully on missing-cache or partial-options.

## File-level plan

### Create

| Path | Purpose |
|---|---|
| `plugin/commands/link-project.md` | The slash command. Frontmatter + flow. |

### Modify

None. PR 1 already added `.claude/project.json` to `.gitignore`. PR 2's specifier already documents the degrade behavior (referenced cross-PR).

## Tests

Manual:
- Run against a real GH-free user project: cache is valid JSON, contains all 9 options if configured (or null for missing).
- Run against a GH-org org project: same.
- Re-run: idempotent (no duplicate keys).
- Run with `task_management: linear` in sdlc.yml: halts cleanly with the intended error.

## Out of scope

- Auto-creation of Status options (gh CLI cannot).
- Linear/Jira analogues.
- Multiple projects per repo.
