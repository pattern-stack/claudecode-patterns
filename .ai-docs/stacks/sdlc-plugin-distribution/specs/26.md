# Add SessionStart `discover-tracker` hook + dispatcher (formerly `/sdlc:link-project`)

## Goal

Auto-populate per-session task-management adapter context (project IDs, field IDs, option IDs, etc.) once per session via a `SessionStart` hook + pluggable dispatcher. Centralized so any agent can read it; pluggable so Linear / Jira can opt in later without changes to specifier or other consumers.

## Approach (revised after PR #39 review)

**Original design** (closed): top-level `/sdlc:link-project <url>` slash command writing `.claude/project.json`. PR review pushback (issue #20-style "this is domain-specific"): a top-level command for one vendor's discovery violates the plugin's vendor-agnostic stance.

**Revised design** (this spec):

1. **`plugin/scripts/discover-tracker.sh`** — single entry point. Reads `task_management:` from `sdlc.yml`. `case`-dispatches to per-vendor functions: `discover_github` (active), `discover_linear` (stub for v1), `jira` (not implemented). Each adapter emits a markdown context block to stdout, or silent-no-ops on missing prerequisites.

2. **SessionStart hook** in `plugin.json` runs `discover-tracker.sh` synchronously, redirects stdout to `${CLAUDE_PROJECT_DIR}/.claude/.session/tracker-context.md`. Empty file is fine — the `@`-mention below becomes a no-op.

3. **Specifier** (and any other consumer) `@`-mentions `.claude/.session/tracker-context.md` in its prompt. No vendor-aware code in agents — they just read the discovered context.

4. **`.gitignore`** excludes `.claude/.session/` (regenerated each session; never committed).

## Tests

- Smoke (run): `mkdir -p .claude/.session && bash plugin/scripts/discover-tracker.sh > .claude/.session/tracker-context.md`
  - With `project_number:` unset → empty file (verified locally).
  - With `project_number:` set → markdown block with project + Status field + options (verified locally against pattern-stack/projects/1).
- Idempotent re-run on every SessionStart.
- `just sdlc::verify` passes.

## Out of scope

- Linear discovery implementation (v2 — `discover_linear` stub stays).
- Jira adapter.
- Programmatic creation of GH Project Status options (gh CLI cannot).
- Caching with TTL — discovery is one fast GraphQL call; runs once per session; cost is negligible.
- Multiple projects per repo (rare; out of v1 scope).

## Why this is better than the original `/sdlc:link-project`

- **Vendor-agnostic surface**: no top-level GitHub-specific slash command leaking into the plugin's command palette.
- **Centralized**: any agent (specifier today, validator/coordinator tomorrow) just `@`-mentions the cached file. No code duplication.
- **Pluggable**: adding Linear / Jira is a function in `discover-tracker.sh`. No changes to specifier or any other consumer.
- **Lazy-zero-config-tolerant**: missing config → empty file → agents degrade naturally. No setup step required for users who don't link a project.
- **Reviewer feedback addressed**: directly responds to the "this is domain-specific" pushback on the prior design.
