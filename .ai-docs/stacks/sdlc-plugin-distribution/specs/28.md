# Restructure repo into native Claude Code plugin layout (`plugin/` + dogfood symlinks)

## Goal

Convert the repo from a `cp -r .claude/` distribution into a native Claude Code plugin (`sdlc`) installable via `/plugin marketplace add` + `/plugin install`. Preserve dogfood-ability via symlinks so this repo continues to use its own SDLC after the restructure. **No behavioral change** — this PR is logic-light, file-heavy. PR 2 is where opinion code lands.

## Approach

Vendor everything currently at `.claude/<dir>/` into `plugin/<dir>/` (the plugin package). Marketplace `source.path: "plugin"`. Dogfood `.claude/` becomes a thin compositional surface: keeps `sdlc.yml` (project config) + symlinks to plugin contents (so live edits to `plugin/agents/planner.md` reflect immediately when running this repo's own loop). Hooks migrate from project `.claude/settings.json` to plugin manifest's `components.hooks`.

Five mechanical sub-steps, in order:

1. **Move plugin contents** to `plugin/<dir>/` (agents, canvases, commands, hooks, output-styles, primitives, scripts, skills). `.claude/{ai-docs,docs}` stay at `.claude/` (internal docs, not shipped).
2. **Plugin manifest** at `plugin/.claude-plugin/plugin.json` declaring components + hooks. Repo-root `marketplace.json` with `source.path: "plugin"`.
3. **Justfile split**: `Justfile` recipes move to `plugin/sdlc.justfile`. New repo-root `Justfile` carries `mod sdlc '.claude/sdlc.justfile'`. `.claude/sdlc.justfile` is a symlink → `../plugin/sdlc.justfile`.
4. **Dogfood symlinks** at `.claude/<dir>` → `../plugin/<dir>` for every shipped dir. Empty `.claude/settings.json` (hooks now declared in plugin manifest).
5. **`sdlc.example.yml`** at `plugin/sdlc.example.yml` (templated copy of dogfood `.claude/sdlc.yml` with placeholder values + `gate1_default: strict` docstring).

Plus path audit — sweep agent prompts for `.claude/<dir>/` references and replace with project-first / `${CLAUDE_PLUGIN_DIR}` fallback language for canvases + primitives. `@.claude/sdlc.yml` reference stays intact.

Plus CI — add a fresh-project install-smoke drift-test job alongside existing invariants.

## Open questions

Reserved as spec-phase confirmations during implementation; none block kickoff:

- **Plugin-shipped command namespacing**: confirm via drift-test that plugin commands invoke as `/sdlc:<cmd>` and that un-prefixed forms do not resolve. Affects PR 6 phrasing only — PR 1 ships namespaced commands regardless.
- **Hook script path** under plugin: existing `emit.mjs` references `${CLAUDE_PROJECT_DIR}` which it uses to locate the project's `agent-logs/` dir. Plugin migration changes the script's *location* (`${CLAUDE_PLUGIN_DIR}/hooks/emit.mjs`) but the script keeps writing to `${CLAUDE_PROJECT_DIR}/agent-logs/`. Verify `${CLAUDE_PROJECT_DIR}` is exposed to plugin-shipped hook scripts at runtime; if not, either inline-resolve or document as v2.
- **Canvas + primitive fallback semantics**: spec says "project-first / plugin-fallback." For PR 1 this is a *prompt-language* change (agent prompts say "look at `.claude/canvases/<name>/` first, then `${CLAUDE_PLUGIN_DIR}/canvases/<name>/`"). No actual fallback code is added — agents handle it via their existing Read tool calls. v2 may formalize via a resolution helper.
